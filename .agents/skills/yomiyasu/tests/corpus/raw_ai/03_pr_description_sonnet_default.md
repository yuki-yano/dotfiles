認証トークンのリフレッシュを、リクエスト処理中に同期で実行する方式から、非同期キューによるバックグラウンド実行へ変更しました。

従来は、アクセストークンの期限切れを検知するたびに認可サーバーへリフレッシュ要求を送り、完了を待っていました。そのため認可サーバーの遅延がそのままAPIのレスポンスタイムに反映されていました。同一ユーザーの並列リクエストが、重複してリフレッシュを実行する問題もありました。

今回の変更では、期限切れが近いトークンをキューに登録し、ワーカーがリフレッシュを処理します。同一ユーザーのジョブはユーザーID単位で重複排除します。失敗した場合は指数バックオフで最大3回まで再試行します。上限に達したときは、再ログインを促す状態へ遷移させます。

重複排除と再試行の挙動について、テストを追加しました。本番反映の前に、ステージングでワーカーの並列数を確認する予定です。
