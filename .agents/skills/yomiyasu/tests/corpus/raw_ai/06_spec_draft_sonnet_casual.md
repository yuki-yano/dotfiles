# 決済Webhook受信：リトライ制御とDLQ 仕様書（ドラフト）

決済プロバイダからのWebhookは、受信時に署名を検証してイベントIDで重複排除し、ペイロードをキューへ積んだ時点で200を返す。業務処理は非同期ワーカーが担当する。プロバイダ側の再送で二重処理が起きないよう、イベントIDをキーにした冪等性をワーカー側でも保証する。

処理に失敗したら、指数バックオフにジッタを加えて最大6回までリトライする。間隔は初回30秒から始めて倍々に伸ばし、上限は1時間とする。リトライ対象は5xx、タイムアウト、DB接続エラーなど一時的な障害に限る。バリデーションエラーや未対応のイベント種別のように、何度やっても結果が変わらないものは即座にDLQへ送る。

6回失敗したメッセージもDLQへ移す。DLQには元のペイロード、失敗理由、試行履歴を残し、保持期間は14日とする。DLQの件数が10件を超えたらSlackに通知し、運用担当が原因を調べる。復旧後は管理画面から単体または一括で再投入できるようにする。
