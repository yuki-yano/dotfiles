# 次期API基盤の技術選定メモ

次期API基盤として、REST APIとGraphQLを比較した。

GraphQLは、クライアントが必要なフィールドだけを指定して取得できる。モバイルとWebで画面ごとにデータ要件が異なる現状では、過剰取得と複数回のリクエストを減らせる。一方で、N+1問題への対策、クエリの深さや複雑度の制限が必要になり、HTTPキャッシュも効きにくい。運用の負担は増える。

RESTはHTTPの標準機能をそのまま使えるため、CDNキャッシュ、監視、認可の設計が容易である。チームに実績があり、学習コストも低い。ただし画面ごとの要件変化にはエンドポイントの追加で対応するため、改修が増えやすい。

結論として、外部公開APIと基幹系はRESTを維持する。フロントエンド向けのBFF層に限ってGraphQLを導入し、一つの画面群で効果と運用負荷を検証したうえで、拡大するかを判断する。
