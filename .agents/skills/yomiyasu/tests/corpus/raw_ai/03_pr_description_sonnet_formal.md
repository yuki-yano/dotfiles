本PRでは、認証トークンのリフレッシュ処理を同期実行から非同期キュー方式へ変更しました。従来は API リクエストの処理中にトークンの再発行を直列で待機していたため、認証基盤の遅延がそのままレスポンスタイムに反映されていました。変更後は、有効期限が近づいたトークンをリフレッシュ要求としてキューへ登録し、専用ワーカーが順次処理します。同一ユーザーの重複要求は冪等キーで集約し、二重発行を防止します。失敗したジョブは指数バックオフで再試行し、上限回数を超えた場合はデッドレターキューへ退避して監視アラートを発報します。既存のエンドポイント仕様に変更はなく、クライアント側の対応は不要です。レビューでは、キューの再試行設計と、ワーカー停止時にトークンが失効するまでの猶予時間の妥当性を重点的にご確認ください。
