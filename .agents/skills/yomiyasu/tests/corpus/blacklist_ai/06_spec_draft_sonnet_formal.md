# 決済Webhook受信におけるリトライ制御およびDLQ 機能仕様（ドラフト）

## 1. 受信処理
決済プロバイダからのWebhookを受信した時点で署名を検証する。検証に成功したイベントはイベントIDとともにキューへ永続化し、直ちにHTTP 2xxを返却する。業務処理は非同期ワーカーが実行する。

## 2. 冪等性
イベントIDを一意キーとして処理状態を記録する。同一イベントが重複配信された場合、業務処理は再実行しない。

## 3. リトライ制御
一時的エラー（タイムアウト、5xx応答、DB接続障害）による失敗は、指数バックオフで最大8回まで再試行する。初回間隔は30秒、係数は2、上限は1時間とし、±20%のジッタを付与する。署名不正やスキーマ不整合などの恒久的エラーは再試行せず、直ちにDLQへ移送する。

## 4. DLQ
再試行上限に達したイベントは、元ペイロード、失敗理由、試行履歴とともにDLQへ格納する。保持期間は14日とする。DLQに1件以上が滞留した時点で運用担当へ通知する。

## 5. 再処理
運用担当は管理機能からDLQイベントを個別または一括で再投入できる。再投入操作は実施者と日時を含め、監査ログに記録する。
