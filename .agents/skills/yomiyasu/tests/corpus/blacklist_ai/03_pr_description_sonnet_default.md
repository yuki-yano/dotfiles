認証トークンのリフレッシュ処理を、リクエスト内の同期呼び出しから非同期キューによるバックグラウンド処理へ移しました。

## 変更の背景
従来は、アクセストークンの期限切れを検知したリクエストがその場でリフレッシュAPIを呼んでいました。同時に複数のリクエストが届くと、同じリフレッシュトークンで重複してAPIを叩き、後続のリクエストが失敗する事例がありました。レスポンス時間もリフレッシュの待ち時間の分だけ延びていました。

## 変更内容
- 期限の5分前になったトークンをキューに登録し、ワーカーがリフレッシュするようにしました。
- ユーザー単位のキーで重複登録を防ぎ、同時実行を1件に制限しています。
- 失敗時は指数バックオフで最大3回再試行し、それでも失敗した場合はセッションを無効化します。
- 同期処理は、期限切れ直前のリクエスト用にフォールバックとして残しています。

## 確認方法
ユニットテストを追加し、並行リクエスト100件でリフレッシュが1回だけ実行されることをステージングで確認しました。
