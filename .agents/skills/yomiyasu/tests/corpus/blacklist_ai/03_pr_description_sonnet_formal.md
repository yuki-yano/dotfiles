認証トークンのリフレッシュ処理を、リクエスト処理内での同期実行から非同期キューによるバックグラウンド実行へ変更した。

従来は有効期限切れを検知したリクエストが、その場で認証サーバーへ更新要求を送信していた。このため、認証サーバーの応答遅延がそのままAPIの応答時間に反映され、同一トークンに対する更新要求が並行して重複する問題があった。

本変更では、期限切れ間近のトークンを検知した時点でリフレッシュジョブをキューへ登録し、ワーカーが順次処理する。ジョブにはトークン単位の冪等キーを付与し、重複登録を防止している。失敗時は指数バックオフで最大5回まで再試行し、上限を超えた場合はデッドレターキューへ退避して監視対象とする。

既存の公開インターフェースに変更はない。単体テストに加え、重複登録と再試行上限の統合テストを追加した。
