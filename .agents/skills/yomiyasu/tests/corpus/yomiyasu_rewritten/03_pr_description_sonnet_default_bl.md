認証トークンのリフレッシュ処理を、リクエスト内の同期呼び出しから非同期キューによるバックグラウンド処理へ移しました。

## 変更の背景

従来は、アクセストークンの期限切れを検知したリクエストが、その場でリフレッシュ API を呼んでいました。複数のリクエストが同時に届くと、同じリフレッシュトークンで API を重複して呼び出し、後続のリクエストが失敗することがありました。レスポンス時間も、リフレッシュの待ち時間の分だけ延びていました。

## 変更内容

期限の5分前になったトークンをキューに登録し、ワーカーがリフレッシュするようにしました。ユーザー単位のキーで重複登録を防ぎ、同時実行を1件に制限しています。リフレッシュに失敗した場合は、指数バックオフで最大3回再試行し、それでも失敗したらセッションを無効化します。期限切れ直前に届いたリクエストのために、同期処理をフォールバックとして残しています。

## 確認方法

ユニットテストを追加しました。ステージングでは、並行リクエスト100件を送ってもリフレッシュが1回だけ実行されることを確認しました。
