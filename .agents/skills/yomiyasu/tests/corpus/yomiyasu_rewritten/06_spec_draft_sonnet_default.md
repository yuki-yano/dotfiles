# Webhook受信リトライ制御・DLQ機能仕様 ドラフト版

## 概要
システムは決済プロバイダからWebhook通知を受信し、処理に失敗した通知を再試行する。再試行の上限回数を超えた通知はDLQへ移す。運用担当者はDLQの通知を手動で再処理できる。

## 受信
システムは署名を検証し、通知をキューに保存して、すぐにHTTP 200を返す。非同期ワーカーがキューの通知を処理する。システムはイベントIDを冪等キーに使い、同じ通知を二重に処理しない。

## リトライ
システムが再試行するのは、タイムアウト、5xx、DB接続断といった一時的エラーに限る。再試行の間隔は指数バックオフで決める。初回は30秒後、倍率は2、上限は1時間とし、±20%のジッタを加える。再試行は最大8回まで実行する。署名不正やスキーマ不正といった恒久的エラーは再試行せず、ただちにDLQへ送る。

## DLQ
システムは、再試行の上限を超えた通知と恒久的エラーの通知を、元のペイロード、エラー内容、試行履歴とあわせて30日間保持する。DLQの件数が10件を超えると、システムは運用チームへ通知する。運用担当者は管理画面から、通知を個別または一括で再投入できる。
