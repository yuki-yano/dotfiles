本PRでは、認証トークンのリフレッシュ処理を同期実行から非同期キュー方式に変更しました。従来は、APIがリクエストを処理している間、トークンの再発行が終わるまで順番に待っていました。そのため認証基盤の応答が遅れると、APIのレスポンスも同じだけ遅れていました。変更後は、有効期限が近いトークンのリフレッシュ要求をキューに登録し、専用ワーカーが順に処理します。同じユーザーからの重複した要求は冪等キーで1件にまとめ、トークンを二重に発行しないようにしています。失敗したジョブは指数バックオフで再試行し、再試行回数が上限に達したらデッドレターキューに移して、監視アラートを通知します。既存のエンドポイントの仕様は変わらないので、クライアント側で対応する必要はありません。レビューでは、キューの再試行をどう設計したかと、ワーカーが止まってからトークンが失効するまでの猶予時間が適切かどうかを、特に見ていただきたいです。
