認証トークンのリフレッシュ処理を、リクエスト処理中に同期で実行する方式から、非同期キューを使ってバックグラウンドで実行する方式に変更しました。

従来は、アクセストークンの期限切れを検知するたびに、APIサーバーが認可サーバーへリフレッシュ要求を送り、応答を待っていました。認可サーバーの応答が遅れると、その分だけAPIのレスポンスタイムも延びていました。同一ユーザーが並列にリクエストを送ると、リフレッシュ要求が重複して送られる問題もありました。

今回の変更では、APIサーバーが期限切れ間近のトークンをキューに登録し、ワーカーがリフレッシュ要求を送って新しいトークンを取得します。同一ユーザーのジョブは、ユーザーIDをキーに重複を取り除きます。リフレッシュに失敗した場合、ワーカーは指数バックオフで間隔を空けながら最大3回まで再試行します。3回失敗すると、ワーカーはそのユーザーを再ログインが必要な状態に切り替えます。

重複排除と再試行の挙動について、テストを追加しました。本番に反映する前に、ステージングでワーカーの並列数を確認する予定です。
