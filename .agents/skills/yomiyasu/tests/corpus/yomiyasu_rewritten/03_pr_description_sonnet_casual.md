## 概要
認証トークンのリフレッシュ処理を、リクエスト内で同期的に認証サーバーを呼ぶ方式から、非同期キューに積んでワーカーが実行する方式へ変更した。

## 背景
これまでは、トークンの期限切れを検知したリクエストが、その場で認証サーバーを呼んでいた。朝の一斉ログイン時には同一ユーザーのリフレッシュが重複して認証サーバーのレート制限に達し、レスポンスが数秒返らないことがあった。

## 変更内容
リクエストは期限切れを検知するとリフレッシュ要求をキューに登録し、ワーカーがその要求を処理する。ユーザー単位の重複排除キーを付けたので、同じユーザーのジョブは1件しか登録されない。リフレッシュに失敗した場合は指数バックオフで最大3回までリトライし、3回目も失敗したらセッションを失効させる。

## 確認したこと
ローカルで100並列のリクエストを送り、リフレッシュが1回だけ実行されることを確認した。ステージングでの負荷試験は未実施なので、マージ前に実施日をレビュアーと決めたい。
