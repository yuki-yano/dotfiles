# 障害報告書

件名 高負荷時のDBコネクションプール枯渇によるAPI 504エラー

発生日時 2026年9月28日14:05から14:42までの約37分間

影響 注文APIと会員情報APIで、全リクエストの約35%が504エラーを返した。

## 経緯
キャンペーンを開始したところ、リクエスト数が通常の約3倍に増えた。コネクションプールの上限は20接続だった。重い集計クエリが接続を長く握り続けたため、空き接続を待つリクエストが30秒のタイムアウトに達し、APIサーバーは504を返した。

## 原因
開発チームは、ピーク時の同時接続数より小さい20接続をプール上限に設定していた。また、集計クエリに実行時間の上限を設定していなかった。さらに、負荷試験ではキャンペーン規模のリクエスト数を流していなかった。

## 対応
運用担当者は集計バッチを停止し、プール上限を50に引き上げてアプリケーションを再起動した。14:42にはタイムアウトが出なくなったことを確認した。

## 再発防止策
開発チームは、クエリの実行時間に上限を設定し、集計処理を読み取りレプリカへ移す。運用チームは、プール使用率が80%を超えたら担当者に通知する仕組みを追加し、キャンペーン前には負荷試験を必ず実施する。
