# ドラフト版 決済Webhookのリトライ処理とDLQの機能仕様

## 1. 受信処理
システムは決済プロバイダからWebhookを受信すると、まず署名を検証する。検証に成功したイベントはイベントIDとともにキューへ永続化し、直ちにHTTP 2xxを返す。業務処理は非同期ワーカーが実行する。

## 2. 冪等性
システムはイベントIDを一意キーとして処理状態を記録する。同じイベントが重複して配信された場合、業務処理は再実行しない。

## 3. リトライ制御
タイムアウト、5xx応答、DB接続障害といった一時的エラーで失敗したイベントは、指数バックオフで最大8回まで再試行する。初回の間隔は30秒、係数は2、上限は1時間とし、±20%のジッタを付ける。署名不正やスキーマ不整合といった恒久的エラーは再試行せず、直ちにDLQへ移す。

## 4. DLQ
再試行の上限に達したイベントは、元のペイロード、失敗理由、試行履歴とともにDLQへ格納する。保持期間は14日とする。DLQに1件以上が滞留したら、システムが運用担当へ通知する。

## 5. 再処理
運用担当は管理機能から、DLQのイベントを個別にも一括でも再投入できる。再投入のたびに、システムは実施者と日時を監査ログへ記録する。
