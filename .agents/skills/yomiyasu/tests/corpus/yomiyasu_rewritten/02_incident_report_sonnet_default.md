障害報告書：DBコネクションプール枯渇によるAPIの504エラー

【概要】
高負荷時にデータベースのコネクションプールが枯渇し、APIが約25分間504エラーを返しました。影響を受けたのは注文API、会員情報API、検索APIの3系統で、リクエスト全体の約38%が失敗しました。

【発生日時】
日本時間の2026年9月28日20:05〜20:30

【原因】
キャンペーン告知メールを配信したところ、通常の約3倍のリクエストが届きました。アプリケーションのコネクションプール上限は20に設定していましたが、一部のクエリにインデックスがなく、1件あたりの処理時間が長くなっていました。そのため接続が解放されず、待機リクエストが積み上がって、プールに空きがなくなりました。ゲートウェイのタイムアウトは30秒で、接続待ちが30秒を超えたリクエストに対して504を返しました。

【対応】
20:12にアラートを検知し、20:18にアプリケーションを再起動しました。しかし負荷が続いていたため、エラーが再び発生しました。20:24に該当テーブルへインデックスを追加し、プール上限を40に引き上げたところ、20:30にAPIが正常に応答するようになりました。

【再発防止策】
スロークエリを全件点検し、不足しているインデックスを追加します。プール使用率を監視するアラートを追加します。キャンペーンの前には負荷試験を必ず実施します。あわせて、接続待ちタイムアウトを短縮します。
