# 障害報告書：コネクションプール枯渇によるAPIの504エラー

## 概要
10月1日の12:10から12:48までの38分間、注文APIとマイページAPIがリクエストの約35%に対して504を返しました。

## 原因
キャンペーンを配信した直後に、アクセス数が平常時の4倍に増えました。アプリケーションのコネクションプール上限は20のままでした。さらに在庫照会クエリに集計処理が含まれており、1件の実行に数秒かかっていました。接続がプールに戻らないため、接続を待つリクエストが増え続け、ゲートウェイの30秒のタイムアウトを超えたものから504を返しました。

## 対応
12:25にスロークエリを特定しました。12:32にプール上限を50へ引き上げ、アプリケーションのインスタンスも増やしました。12:48にエラー率が平常値へ戻ったことを確認しました。

## 再発防止
開発チームは在庫照会にインデックスを追加し、集計結果をキャッシュから返すようにします。プール使用率が80%を超えたら、システム管理者に通知するアラートを設定します。大型キャンペーンの前には、必ず負荷試験を実施します。

私たちはプール上限を「とりあえず動く値」のまま放置しがちでした。今回の障害を受け、上限値もキャパシティ計画の対象にすべきだと認識しました。
