認証トークンのリフレッシュ処理を、リクエスト処理内での同期実行から、非同期キューを使ったバックグラウンド実行に変えた。

従来は、有効期限切れを検知したリクエストがその場で認証サーバーへ更新要求を送っていた。認証サーバーの応答が遅れると、その分だけAPIの応答時間が延び、同じトークンに対する更新要求が並行して重複することもあった。

本変更では、期限切れが近いトークンを検知した時点でリフレッシュジョブをキューに登録し、ワーカーが順番に処理する。ジョブにはトークンごとの冪等キーを付け、重複して登録されないようにしている。失敗したジョブは指数バックオフで最大5回まで再試行する。5回を超えたジョブはデッドレターキューに移し、監視の対象にする。

既存の公開インターフェースは変えていない。単体テストに加えて、重複登録と再試行上限の統合テストを追加した。
