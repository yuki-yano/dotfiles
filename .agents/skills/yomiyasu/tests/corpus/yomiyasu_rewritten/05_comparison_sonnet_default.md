# 次期API基盤の技術選定メモ

次期API基盤として、REST APIとGraphQLを比較した。

GraphQLでは、クライアントが必要なフィールドだけを指定して取得できる。モバイルとWebで画面ごとにデータ要件が異なる現状では、過剰取得と複数回のリクエストを減らせる。一方で、開発者はN+1問題への対策を実装し、クエリの深さと複雑度に上限を設ける必要がある。HTTPキャッシュも利用しにくく、運用の負担が増える。

RESTはHTTPの標準機能をそのまま使えるため、CDNキャッシュ、監視、認可を設計しやすい。チームには実績があり、学習コストも低い。ただし画面ごとに要件が変わるたびにエンドポイントを追加するため、改修の件数が増えやすい。

結論として、外部公開APIと基幹系ではRESTを維持する。フロントエンド向けのBFF層に限ってGraphQLを導入し、一つの画面群で導入効果と運用負荷を検証したうえで、適用範囲を広げるか判断する。
