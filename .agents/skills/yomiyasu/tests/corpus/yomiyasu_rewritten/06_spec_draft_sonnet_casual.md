# 決済Webhook受信のリトライ制御とDLQ仕様書（ドラフト）

決済プロバイダからWebhookを受信したら、システムが署名を検証し、イベントIDで重複を除き、ペイロードをキューへ積んだ時点で200を返す。業務処理は非同期ワーカーが担当する。プロバイダが再送しても同じイベントを二重に処理しないよう、ワーカーもイベントIDをキーに処理済みかどうかを確認する。

ワーカーは処理に失敗したメッセージを、指数バックオフにジッタを加えた間隔で最大6回まで再試行する。初回は30秒後に再試行し、以降は間隔を2倍ずつ延ばして、上限を1時間とする。再試行するのは、5xx、タイムアウト、DB接続エラーなど一時的な障害で失敗した場合に限る。バリデーションエラーや未対応のイベント種別のように、何度実行しても結果が変わらない失敗は、再試行せずすぐにDLQへ送る。

6回続けて失敗したメッセージもDLQへ移す。DLQには元のペイロード、失敗理由、試行履歴を保存し、保持期間は14日とする。DLQの件数が10件を超えたらSlackに通知し、運用担当が原因を調べる。運用担当は、復旧後に管理画面からメッセージを1件ずつでも一括でも再投入できる。
