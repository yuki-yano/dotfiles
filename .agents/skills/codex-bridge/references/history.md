# Computer History

保存済みの要約と生イベントを読み取り専用で使う。記録の開始・停止・設定変更はしない。`computer-history`は`history`と同じコマンド。

## 状態

`codex-bridge history status`の`recording_state: unknown`は、現在の収録状態が不明という意味。保存ファイルの更新だけから収録中とは判断しない。

## 要約

```sh
codex-bridge history summaries \
  --start '2026-11-06T09:00:00+09:00' --end '2026-11-06T12:00:00+09:00' \
  [--query 検索語] [--max-chars 20000]
```

- 時刻はタイムゾーン付きのISO 8601。開始を含み、終了を含まない。
- 6時間・10分単位で保存された要約のうち、範囲に完全に収まるものだけを返す。6時間の要約がある範囲では、その内側の10分要約は返さない。
- 6時間要約の区切りはUTC基準（日本時間の3時・9時・15時・21時）。たとえば日本時間12〜18時のように区切りをまたぐ範囲では10分要約が多数返り、`--max-chars`で打ち切られやすい。範囲を区切りに合わせるか、分けて読む。
- `--max-chars`は既定20000、最大100000。10分要約は1件数千文字あり、6時間分では上限を超えやすい。`omitted_documents`や`truncated`があれば、範囲を2時間程度に分けて読む。
- `uncovered_intervals`は要約がない区間。欠測や検索不一致は活動がなかった証拠ではない。

## 生イベント

```sh
codex-bridge history events \
  --start '2026-11-06T11:00:00+09:00' --end '2026-11-06T11:10:00+09:00' \
  [--query 検索語] [--limit 20] [--offset 0] [--details]
```

- 各イベントの`data`はJSONオブジェクト。既定では時刻・種類・アプリ・ウィンドウだけを返す。AX・キーボード・マウス・選択範囲が必要なときだけ`--details`を付ける。
- 長い文字列（AXの画面テキスト等）は約4000文字で切られ、末尾に`…[truncated]`が付き、そのイベントの`truncated`が`true`になる。`--details`は1件で数KBになるため、`--limit`を小さくする。
- `--query`は返す項目に対して一致を見る。`--details`なしではキー入力などの中身には一致しない。
- `has_more: true`なら`next_offset`を次の`--offset`に渡す。`--limit`は1〜100。
- 要約で時間帯を絞ってから、必要な短い範囲だけイベントを読む。
