# Commit Plan

Git差分を意図ごとに整理し、依頼された範囲で計画またはコミットを完了する。

## 実行意図

- 「計画だけ」「実行前に計画を確認したい」なら計画を提示して終了する。
- 「commitして」などの明示指示、または提示済み計画への承認があれば、短く内訳を示して全コミットを実行する。各コミット前に確認し直さない。
- skill名だけの呼び出しや分割の相談は、commit実行の許可とみなさない。計画を提示し、実行希望がある場合は承認を受けてから実行する。

## 差分と計画

`git status`、staged / unstaged diff、untracked一覧、直近のcommit logから、対象範囲と意図を確認する。
`--file <path>`指定時は計画と操作をそのpathspecに限定する。
分類オプションの解釈が必要な場合だけ[引数対応](references/arg-mapping.md)を読む。

- 各コミットの目的、対象ファイル、メッセージを示す。同じ目的の小変更を無理に分割しない。
- メッセージは過去logの形式に合わせる。作業説明・実行コマンド・メッセージ本文を重複して列挙しない。
- 同一ファイルに複数の意図があれば部分ステージングを計画する。
- 計画書として残す場合や複雑な分割では[計画テンプレート](references/plan-output-template.md)を使う。

## 実行

[実行・部分適用](references/execution-and-patch.md)に従う。
全ファイル単位で分けられる場合は通常の`git add -- <file...>`を使う。
部分適用が必要な場合だけpatchを作成する。

コミット前にstaged diffと計画の一致を確認し、コミット後に内容と残りの差分を確認する。
同じ差分で成功済みの検証を各コミットごとに繰り返さない。
hookが依頼内のformat修正を行った場合は、差分を確認して再stage・再試行する。
未検証の挙動が変わる修正は、影響する検証を完了してから進める。

## 確認・停止が必要な場合

- 意図しない差分、対象範囲外のstaged差分、扱いを判断できないuntracked fileがある。
- secretやcredentialらしき値の追加がある。値を出力せず、対象箇所を示す。
- 部分適用後のstaged diffが計画と一致しない、並行編集が混ざった、失敗の影響を特定できない。

これらの場合は対象操作を止めて確認する。commit指示を対象外変更の許可にはしない。
原因が分かる依頼内の修正・再検証は続け、権限変更、hookの無効化、破壊的な巻き戻しで通さない。
復旧が必要な場合は[失敗時の扱い](references/recovery-and-cleanup.md)を読む。

## 完了報告

作成したコミットのhash・要点、実行した検証、残した差分を示す。
途中で止まった場合は、作成済みコミットと未完了の範囲を区別する。
ignoreされたファイルの強制addや、明示指示のないcommit・pushは行わない。
