# 既存UIの監査と改善

このモードは、既存の画面やフローをHIGに照らして監査し、許可された場合に改善するために使う。
監査結果は、現在の画面、操作、コード、自動検査の証拠に結び付ける。

## 監査範囲

ユーザーが指定した画面またはフローを優先する。
指定が広い場合は、利用頻度、失敗時の影響、直近の変更量からprimary flowを選び、対象範囲を明示する。

定期実行では次を対象にする。

1. 前回実行後に変更されたUIと、その変更が影響するフロー
2. 前回残った未解決項目
3. まだ監査していない主要フローのうち、優先度が最も高い一つ

変更されていない画面を毎回全面的に再監査しない。
外観をApple風に近づけること自体を目的に、視覚的なchurnを発生させない。

前回の実行情報がautomation memoryとして渡された場合は、それを利用する。
リポジトリへ監査台帳を新設するのは、ユーザーが求めた場合に限る。

## 証拠の取得

Product Designの`audit`が対象surfaceを操作してcaptureできる場合は、それを使って対象フローをスクリーンショット付きで監査する。
Web、native app、Electron appなどsurfaceに合うUI操作手段を選び、静的なコード調査だけで代用しない。
呼び出すskillは、その実行時に全文を読んで従う。

1. 対象フローを開始状態から完了、error、emptyなど必要な状態まで操作する。
2. 各stepで安定した画面をキャプチャし、保存した画像を実際に確認する。
3. navigation、feedback、validation、loading、error recovery、focus、motionを観察する。
4. コードを読み、スクリーンショットでは判断できないsemantic、keyboard、text scaling、reduced settingsを確認する。
5. 対象に関係するApple公式ページを取得し、findingの根拠として対応付ける。

画面を操作できない場合は、コードだけからvisual auditを完了したと報告しない。

## Findingの記録

各findingには次を含める。

- severity：critical、high、medium、low
- evidence：スクリーンショットのstep、操作結果、コード位置、自動検査結果
- HIG source：判断に使ったApple公式ページ
- problem：現在の状態
- impact：主要タスク、誤操作、理解、アクセシビリティへの影響
- recommendation：仕様を変えない最小の改善案
- verification：修正後に確認する状態と方法

スクリーンショットから確認できる事実と、コードまたは支援技術で検証が必要なリスクを分ける。

## 改善

ファイル変更が許可されている場合だけ改善する。

1. criticalとhighから、仕様が明確で影響範囲を限定できるfindingを選ぶ。
2. 既存のcomponentとtokenを使い、同じ原因を持つ箇所を一貫して修正する。
3. product logicを変える必要があるfindingは、実装前にユーザーへ確認する。
4. 関係する自動検査を実行する。
5. 修正した状態を同じviewportと操作stepで再キャプチャする。
6. findingのverificationを実行し、解消、部分解消、未解消を記録する。

一回の定期実行で広範囲を改装しない。
証拠と検証方法を明確にできる、まとまりのある改善単位で止める。

## 定期実行の記録

次回の実行へ渡す情報を、automationの実行結果またはmemoryへ残す。

- 実行日と対象範囲
- 前回から確認したUI差分
- 新規findingと継続finding
- 実施した修正
- 実行した検証と結果
- 未確認事項とblocker
- 次回監査する主要フロー

リポジトリへ書き込む場合は、既存の保存先と形式があるときだけ使う。

## DoD

### 機能完了条件

- [ ] 対象画面またはフローと監査範囲を明示している。
- [ ] 主要なstepを現在のスクリーンショットまたは名前付きblockerで記録している。
- [ ] findingをseverity、evidence、HIG source、impact、verificationとともに記録している。
- [ ] 改善を依頼された場合は、許可された範囲の明確なfindingを修正している。
- [ ] 未確認事項と未解決項目を残している。

### テスト完了条件

- [ ] 保存したスクリーンショットを実際に表示して確認している。
- [ ] 修正した状態を同じviewportと操作stepで再確認している。
- [ ] 変更に関係するformat、lint、typecheck、test、buildを実行している。
- [ ] keyboard、focus、text scaling、contrast、reduced settingsを対象範囲に応じて確認している。
- [ ] スクリーンショットだけでアクセシビリティ適合を保証していない。

### 運用反映条件

- [ ] 参照したApple公式ページ、変更ファイル、検証結果、残課題を報告している。
- [ ] 定期実行では、次回対象と継続findingをmemoryまたは実行結果へ残している。
- [ ] ユーザーの指示なしに監査台帳を新設していない。
- [ ] ユーザーの指示なしにcommit、push、deployしていない。
