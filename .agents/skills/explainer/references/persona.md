# ペルソナの作り方

ペルソナは、1 人の読み手について **「何を書かなくてよいか」と「どこを書くべきか」** を決めるためのメモ。
型（「エンジニア」「初心者」）ではなく、実在の 1 人を書く。

## 材料

### 1. 本人への質問（聞けるなら最優先、最大 5 問）

1. いまこの分野で、何を使って何をしていますか。
2. 最近どこで手が止まりましたか。自信がなくなったのはどの部分ですか。
3. 読むのに使える時間はどれくらいですか。
4. 説明は、コードから入るのと、図から入るのと、どちらが速いですか。
5. 読み終えたら、何を自分で判定できるようになりたいですか。

5 番の答えが、資料の「問い」になる。

### 2. 公開情報

- GitHub：最近のリポジトリ、README、docs、書いたスキル
- ブログ・登壇資料・gist
- 文体：本人の文章の段落の長さ、文の長さ、よく使う語

主張には、1 つずつ出典 URL を付ける。
**事実（出典つき）と推測を別の欄に書く。**
推測は本人に確認するまで仮説として扱う。

## テンプレート

```markdown
# <id>

- 作成日 / 材料: 質問 (有無), 公開情報 (URL 一覧は末尾)
- 読み手と書き手が同一人物か: yes / no / 不明

## 背景（事実）
- 主に使う言語・領域 — 出典

## この分野で既に知っていること（事実）
- 使っているツールと、どう使っているか — 出典
- 本人が書いた・言ったこと（引用） — 出典

## 怪しいところ（推測。資料の芯になる）
- 「使える」と「結果の意味を判定できる」の間にある差
- 本人が詰まったと書いている箇所

## 読み方
- 言語、段落の長さ、コード先か図先か、読む時間

## この資料で省くもの
- 「既に知っていること」から導く（ツール紹介、インストール、一般論など）

## 未確認（本人に聞くこと）
- 答えで資料の中身が変わる質問だけ。答えが来たら、該当する推測を事実に移して消す

## 出典
```

## 答えがまだ無いとき（仮のペルソナ）

名前と所属しか分からなくても、ファイルは先に作る。質問して止まる場合も同じ。
あとで答えが来たとき、何を推測していたかが残っていないと、資料のどこを直すか分からないため。

```markdown
# tanaka-hanako

- 作成日 / 材料: 依頼文のみ。質問は未回答
- 状態: 仮（推測のみ）

## 背景（事実）
- 決済チームのバックエンドエンジニア — 依頼文

## この分野で既に知っていること（推測）
- Dockerfile を読める。BuildKit のキャッシュは既定のまま使っている — 職種からの推測

## 未確認（本人に聞くこと）
- CI のランナーは毎回使い捨てか
- ビルドで遅いと感じているのはどの段階か
```

「事実」の欄には、依頼文か出典で確かめたことだけを書く。

## 注意

- 公開情報から作ったペルソナは、公開情報の偏りをそのまま持つ。書いていないことを知らないとは限らない。
- 本人以外のペルソナは、本人に見せられる内容だけを書く。私生活や、仕事に関係のない情報は集めない。
- ペルソナは資料ごとに更新する。理解度チェックで答えられなかった問いは、「怪しいところ」に戻す。
